# dsh-pet-voice 🎤

右键点桌宠 → 「语音控制」→ 说一句话，桌宠照着做。

## 怎么用

1. 确认 **dsh-pet** 已安装并启用（桌宠在桌面上）。
2. **右键点桌宠**，菜单最后面的「更多」里有 **语音控制**。
3. 点它，桌宠弹一句「我在听…」，开始录音 **8 秒**。
4. 说完它把这句话变成动作，并弹气泡告诉你它理解成了什么。

录音在宿主侧完成，**不需要开着 DSH 网页**，也不需要按任何额外的按钮。

## 会听懂什么

| 你说 | 桌宠做什么 |
| --- | --- |
| 跳个舞 / 女仆舞 / 宅舞 | 播对应舞蹈 |
| 睡吧 / 晚安 / 去睡 | 睡下 |
| 醒醒 / 起床 | 醒来 |
| 到左边 / 到右边 / 回来 / 上去 / 下来 | 走到对应位置 |
| 扔出去 / 甩出去 | 被甩飞 |
| 吃白饭 / 吃西瓜 / 涮火锅 / 吃零食 | 播对应吃东西动画 |
| 魔方 / 撸猫 / 放烟花 / 堆雪人 / 收红包 | 播对应动画 |

也可以直接说动作的完整名字（「原地专心玩魔方」「悠闲哼歌」）。

认不出来时桌宠会弹「没听懂」，并把原话一起带出来——这样你能看出是**识别错了**还是**没匹配上关键词**，换个说法即可。

## 对话也能控制桌宠

除了右键语音，**直接在 dsh-pet 的对话框里打字**也能让它动起来：

| 你说 | 它做什么 |
| --- | --- |
| 晚安，早点休息 | 睡下 |
| 醒醒 | 醒来 |
| 你到右边去待着吧 | 走到右边 |
| 回中间来 | 回到中间 |
| 上去一点 / 下来一点 | 走到上方 / 下方 |

原理：插件借 dsh-pet 暴露的 `petApi7340.memory.register` 挂了一个记忆后端——

- **对话前**（`recall`）往 system 里追加一份控制指令说明，告诉模型可以写 `[控制:sleep]`、`[控制:move-right]` 这类标记；
- **对话落盘后**（`capture`）解析回复里的标记，调 `/sleep`、`/wake`、`/throw`、`/position` 执行。

dsh-pet 自带的对话动作联动（`[动作:名称]`）只能播动画，睡觉 / 走动 / 抛掷走的是另外的端点，插不进去——所以另开了一条标记通道。

**不会抢别人的记忆后端**：dsh-pet 的记忆槽是单槽，插件只在「当前没有第三方后端」时才注册。

## 为什么录音在宿主侧

宠物活在 dsh-pet 的桌面 Electron 窗口里，那个窗口加载的是 dsh-pet 自己的页面，本插件的代码不在里面。而浏览器录音要求页面处于焦点、需要用户手势、还要麦克风权限——右键点的是桌面窗口，不是网页。

宿主侧录音绕开全部这些问题：点完菜单直接录，与页面是否打开无关。

## 为什么用 Python

这台机器的麦克风原生格式是 **4 声道 / 48000 Hz / 32 位浮点**（`WAVE_FORMAT_EXTENSIBLE`）。Windows 的 `waveIn` 老接口只吃整数 PCM，协商会「成功」但一个采样都录不到（实测 `dwBytesRecorded = 0`、`waveInGetPosition = 0`）。

所以必须走 WASAPI 拿原生混音格式，再自己重采样成 ASR 要求的 16 kHz / 单声道 / PCM16。Node 没有现成的 Windows 音频库，而 Python 用 `ctypes` 调 COM 就行，**零第三方依赖**。

## 识别走哪条路

插件**直接**把音频发给 DeepSeek 官方语音识别接口：

```
POST https://api.deepseek.com/v1/tools/asr
  multipart/form-data，file 字段放 16kHz 单声道 PCM16 WAV
→ { "request_id": "...", "text": "跳个舞", "duration_ms": 2990 }
```

- 音频格式：16 位 PCM WAV 或 Ogg Opus，单声道或双声道（双声道只识别左声道），最长 120 秒、最大 8 MiB；
- 鉴权：DSH 凭据里的 `DEEPSEEK_API_KEY`，经 `ctx.credentials` 每次现取；
- 不经 dsh-pet 中转，也不需要装 DSH 官方语音输入插件。

**密钥不缓存、不落盘、不进日志**，每次识别取一次、用完即弃。

错误按状态码给出可读提示：401/403 说 Key 无效，400 说音频格式不对，413 说录音太大，429 说太频繁，503/504 说服务忙。
## 排查

插件把关键步骤写进包目录下的 `voice.log`（不记音频内容、不记 API Key）：

- 录音失败：`录音失败：<reason> <message>`
- 识别失败：`识别失败：<reason> <detail>`
- 识别成功：`识别到「...」`——看出是听错了还是没匹配上关键词
- 未捕获异常：完整堆栈

路径：`<插件目录>/voice.log`（装在 profile 里时是 profile 的 `node_modules/dsh-pet-voice/voice.log`）。

## 配置

Python 解释器路径可用环境变量 `DSH_PET_VOICE_PYTHON` 覆盖。不设时自动探测：

- Windows：`C:\python\python.exe` → `C:\Python313\python.exe` → `C:\Python312\python.exe` → PATH 上的 `python`
- 其它：`/usr/bin/python3` → `/usr/local/bin/python3` → `/opt/homebrew/bin/python3` → PATH 上的 `python3`

## 限制

- 需要 **dsh-pet 0.4.9+**（`/menu/item` 与 `/anim` 等动作端点由它提供）。
- 需要已配置 `DEEPSEEK_API_KEY`，否则桌宠提示「没配 DEEPSEEK_API_KEY，认不了语音」。
- 需要本机有 **Python 3**（实测 3.13）。
- 单次录音固定 8 秒；识别按音频时长计费。
- 录制的是默认录音设备（WASAPI 序号 0）。
